# Перевірка WNX Session Tracker у WoT EU

Candidate `0.9.19-dev.3` для клієнта `2.4.1.1 #993`. Початкова перевірена версія мода — `0.9.18`. [Аудит джерел, архітектури й ризиків](SESSION_TRACKER_AUDIT.md).

## Встановлення й відкат

1. Закрийте WoT. Збережіть копії `mods/2.4.1.1/gg.unicum_0.9.18.wotmod` і `mods/configs/unicum/settings.json`. Якщо тестуєте скидання на наявній вибірці, окремо збережіть `mods/configs/unicum/wnx_tracker/`.
2. Перенесіть попередній `.wotmod` за межі каталогів, які сканує клієнт. Залиште один Unicum `.wotmod` і одну копію сумісного `net.openwg.gameface`. У ZIP є оригінальна збірка Gameface 1.2.2 для інсталяцій, що її потребують.
3. Покладіть `gg.unicum_0.9.19-dev.3.wotmod` у `mods/2.4.1.1/` та запустіть клієнт звичайним способом. Відкрийте налаштування шестернею в Tracker.
4. Для відкату закрийте гру, поверніть `.wotmod` версії 0.9.18 і за потреби відновіть збережений `settings.json`. У 0.9.18 журнал Tracker не читається.

## Стан перевірок

| Сценарій | Доказ |
|---|---|
| Точна формула, нульові знаменники, 10/20/30, екстремуми | 26 наборів від оригінальної TypeScript-функції, Python 2.7, допуск `1e-6` |
| Random, ідентифікація, повтори, відкладені результати та replay gate | Автотести з реальним replay-derived fixture та симульованими подіями |
| Пошкоджений хвіст журналу, помилка запису, retry, ізоляція акаунтів/регіонів і reset | Python 2.7 selftest |
| Таблиця expected values, формат, кеш, відсутність мережі | HTTP GET до джерела Unicum.gg повернув 1007 рядків, тестові `intCD` присутні. Selftest перевіряє втрату мережі, пошкоджений кеш і відкладений запис. |
| 30 стовпчиків, адаптивний Y, підказки та clamp | AS3 fixtures виконують методи самого SWF у тестовому оточенні для 10/20/30 боїв, 1280×720–2560×1440 та 100–200% |
| Старі екрани й опційний API | Чотири наявні JS перевірки, тест байткоду modsSettingsApi 1.7.1 і побайтове порівняння бойових SWF з 0.9.18 |
| Пакування | Apache Royale з бібліотеками встановленого `2.4.1.1 #993`, Python 2.7 `release_check.py` |
| Базовий запуск та вигляд | WoT EU 1920×1080, встановлений набір модів. `dev.1` відкрив віджет, шестерню, General, WNX Tracker та червоне підтвердження. Apply змінив мову на UK та зберіг її. Cancel лишив N=20 після редагування N на 30. |
| Кеш після запуску | `dev.2` записав перевірену таблицю в `wnx_tracker/expected.json` у встановленому клієнті. |
| Escape та шар системного меню | У `dev.2` Escape також відкривав меню WoT, а Tracker міг його перекривати. `dev.3` поглинає Escape в диспетчері гри, коли вікно Tracker відкрите, і приховує Tracker на час показу штатного меню або налаштувань. Обидві гілки поки підтверджені fixtures. |

Відтворення candidate з кореня репозиторію після підготовки flags та icons за [інструкцією збірки](DEVELOPMENT.md):

```powershell
python tools/build_as3.py --game F:/Games/World_of_Tanks_EU
python tools/build_release.py --version 0.9.19-dev.3 --game F:/Games/World_of_Tanks_EU --python27 PATH_TO_PYTHON27
& PATH_TO_PYTHON27 tools/selftest.py
& PATH_TO_PYTHON27 tools/release_check.py dist/gg.unicum_0.9.19-dev.3.wotmod
node tools/check_tracker_ui.mjs
```

## Матриця приймання в клієнті

- [ ] Запустіть клієнт з чистою історією Tracker. Перевірте `0/20`, доступність шестерні та відсутність віджета до входу в ангар.
- [ ] Перемкніть обома стрілками `Mini → Compact → Trend → Battles → Mini`. У Mini звірте загальний `total.wnx` з профілем, зокрема без локальної історії. У решті режимів перевірте лічильник і повідомлення для `0/N`, `N−1/N` і `N/N`.
- [ ] Зіграйте випадковий бій і дочекайтеся результату. Переконайтеся, що запис належить вашому акаунту та має правильний танк, час, шкоду, асист і результат. Відкрийте той самий звіт повторно. Очікується один запис. Перевірте також результат, який надійшов із затримкою. Зіграйте в іншому режимі та відкрийте реплей. Переконайтеся, що лічильник не змінився.
- [ ] Для перевірки незалежності від uploader використайте QA-копію з вимкненим серверним consumer. У штатній 0.9.18 для надсилання результатів немає перемикача. Згода на replay uploads і приватність сторінки боїв мають окрему поведінку.
- [ ] Для кожного N порівняйте останнє значення Trend з агрегованим WNX поточних N боїв. Перша точка існує лише при N боях. Після `2N` звірте Δ із різницею двох неперекривних вікон.
- [ ] У Battles з 30 записами перевірте всі 30 позицій від найстарішої до останньої. Послідовно наведіть курсор на першу, середню, останню та дві сусідні позиції. Звірте назви техніки й показники зі звітами. Окремо перевірте високе значення, реальний нуль і пропуск expected data.
- [ ] Перевірте 1280×720, 1366×768, 1920×1080 і 2560×1440 на доступних масштабах UI. Перетягніть віджет за заголовок без Ctrl до кожної межі. Перевірте, що кнопки не рухають віджет, деталі відкриваються вгору біля нижнього краю, клік закріплює їх, довга назва танка вміщується в підказці, а перезапуск відновлює положення.
- [ ] Перейдіть між усіма п’ятьма категоріями EN/UK. Звірте Panels, Tab, Loading, Markers і решту наявних функцій. Прокрутіть найдовші групи, перевірте навігацію Tab, вибір у списку й текстове поле Twitch. Перевірте Apply, OK, Cancel, X і Escape, зміну зовнішньої конфігурації та одночасне відкриття старого UI.
- [ ] На акаунті з тестовою історією відкрийте reset і скасуйте його через кнопку, X та Escape. Потім підтвердьте. Перевірте `0/N`, незмінний Mini WNX і відсутність відновлення старого результату після повторного відкриття звіту, рестарту й відповіді, затриманої до reset. Повторіть з іншим акаунтом. Окремо протестуйте відновлення позиції та типових параметрів.
- [ ] Перевірте теми з низьким і високим WNX, числом без кольорової шкали та без локальних даних. Порівняйте відтінок віджета, вікна та модального діалогу. Кнопка скидання залишається червоною в кожній темі.
- [ ] Повторіть у конфігураціях з/без modsListApi та modsSettingsApi. Після першого успішного відкриття власного вікна перевірте, що дубль у треї прибрано. У тестовій інсталяції з попереднім lobby-SWF перевірте аварійний доступ через стандартні налаштування WoT.
- [ ] Перевірте перехід у бій, повернення, logout/login і повторне відкриття вікна. В бою перевірте Alt, Tab, маркери і панелі команди. Зіставте `game.log` з моментом переходу та стежте за дублями view, повідомленнями Scaleform, винятками Tracker і просіданнями FPS.

Локальний журнал містить лише метрики Tracker. Вага асисту `0.67` застосовується в WNX. У підказці «Сумарка» складається з власної шкоди та повного асисту розвідкою і гусеницями. Таблиця expected values кешується з датою джерела та хешем. За першого запуску офлайн місцеві результати накопичуються, а WNX буде доступним після отримання таблиці.
